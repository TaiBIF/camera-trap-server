Data Package 內容

每個計畫匯出為一個資料夾，內含一個詮釋資料檔與三個資料表。三個資料表以 ID 互相關聯：

deployments.csv
一列 = 一台相機在一個地點的一段運作期間
以 deploymentID 被 media 與 observations 引用
media.csv
一列 = 一張照片
以 deploymentID 指向所屬的 deployment
observations.csv
一列 = 一筆辨識結果
以 mediaID 指向照片；一張照片可有多筆辨識

datapackage.json 則記錄計畫名稱、授權、主持人、資料的空間範圍與時間範圍，以及資料中出現的所有物種清單（含 TaiCOL 編號與中文名）。

三個計畫的資料

計畫 287、288 含有 TaiCAT 舊系統移轉進來的資料，計畫 329 則完全是現行系統上傳的資料。兩者在資料庫中的結構不同，因此 deployment 的產生方式也不同（詳見兩種 deployment）。

兩種 deployment：現行系統與舊系統

Camtrap DP 定義的 deployment 是「一台相機在一個地點運作的一段期間」。TaiCAT 依照片有沒有連結到工作紀錄，用兩種方式產生 deployment：

工作紀錄型 j-位置型 dep-
適用資料現行系統上傳、連結到工作紀錄的照片
329 全部 287、288 部分		舊系統移轉的照片，以及未連結工作紀錄的照片
287、288
一個 deployment 代表一次架設到回收的期間一個相機位置的全部照片
deploymentStart / End工作紀錄登記的起訖時間該位置照片的最早與最晚拍攝時間
同一位置多次架設分成多個 deployment合併成一個 deployment

為什麼舊系統資料要用位置型？舊系統只記錄了照片與相機位置，沒有每次架設、回收的起訖時間。若把整個計畫當成一個 deployment，所有樣點的座標會混在一起；若每張照片當成一個 deployment，運作期間會是 0。以「一個位置 = 一個 deployment」折衷，保留了樣點的真實座標，並以照片時間推估運作期間。

計算努力量（相機工作時數）時請注意：dep- 佈設的期間是從第一張到最後一張照片，中間若有相機停機或多次回收的空檔也會算進去，因此會高估工作時數。j- 佈設的期間則來自實際的工作紀錄，較精確。建議分析時以 deploymentID 前綴區分兩者。

計畫 287、288 同時有兩種 deployment：有工作紀錄的照片歸在 j-，其餘歸在同一位置的 dep-，兩者以 locationID 對應到相同的相機位置。每張照片只會出現在其中一種，不會重複。

物種標籤分類

TaiCAT 沒有獨立欄位記錄「這是不是測試照、空拍」，這些資訊寫在物種標籤中。匯出時依標籤轉換為 Camtrap DP 的受控詞彙：

做物種分析時，篩選 observationType = animal 即可排除測試照、空拍與工作照；這些照片仍保留在資料中，可用來確認相機的運作期間。

學名對應（TaiCOL）

資料庫中的物種為中文俗名，匯出時透過臺灣物種名錄 TaiCOL 對應為拉丁學名與 TaiCOL 物種編號，並經人工校正，例如：

  • 別名與全名對應到同一物種：「野山羊」「山羊」「臺灣野山羊」皆為臺灣野山羊 Capricornis swinhoei；「臺灣山鷓鴣(深山竹雞)」「深山竹雞」皆為 Arborophila crudigularis。
  • 臺灣僅有單一亞種者，對應到該亞種：「野豬」為 Sus scrofa taivanus。
  • 使用 TaiCOL 目前的有效學名：「台灣噪眉」為 Trochalopteron morrisonianum，不使用已刪除的舊名。

無法對應到單一物種的標籤，例如「鼠或鼩形目」「鳥」「松鼠」「無法辨識」「白氏/虎斑地鶇」，observationType 維持 animal、scientificName 留白，原始標籤保留在 observationComments 開頭。

時間與座標

  • 時間：照片時間在資料庫中以 UTC 儲存，匯出時轉為台灣時間（+08:00）；工作紀錄的起訖時間原本即為台灣時間。
  • 座標：計畫 329 大部分相機位置以 TWD97 二度分帶（TM2 121 分帶，公尺）登錄，匯出時轉換為 WGS84 經緯度（EPSG:3826 → EPSG:4326）。原本已是經緯度的資料不變。
  • timestampIssues：符合以下任一條件時標記為 true，照片本身仍會匯出：
    • 佈設或照片的時間早於 2000-01-01，或晚於匯出日期（相機時鐘重設、設定錯誤）。
    • 照片時間超出該佈設起訖期間 1 天以上。
    標記數量：287 有 7 個佈設、288 有 2 個、329 有 31 個。

排除與合併規則

  • 標記為重複上傳的照片不匯出。
  • 已停用的相機位置不匯出。
  • 測試用的相機位置（以預設座標 1, 1 登錄者，如計畫 329 的 test、test0621 等）及其照片不匯出。
  • 真實人員入鏡照（見上表）不匯出。
  • 缺少拍攝時間的照片、缺少座標或起訖時間的佈設不匯出，以符合 Camtrap DP 必填規定。
  • 工作紀錄若被標記為無效或停機空檔，該紀錄的照片不匯出。
  • 同一張照片有多筆辨識時（例如拍到兩種動物），media.csv 只列一次，observations.csv 則每筆辨識各一列。

使用注意事項

座標可疑的相機位置：下列位置的座標在原始資料庫中即有誤，不在臺灣範圍內，進行空間分析前請排除或自行校正：

  • 計畫 287、288：HL13B（緯度 2.337…，疑為 23.37 的誤植）。
  • 計畫 288：LD-LTMM-023（緯度 20.998…）。
  • 努力量：dep- 佈設的運作期間為照片時間推估，會高估工作時數，見兩種 deployment。
  • 事件：未將連拍照片合併為獨立事件，每張照片為一筆紀錄。計算相對豐度（OI 值）時，請依研究設計自行定義有效照片間隔（例如同位置同物種 30 分鐘或 1 小時內視為同一事件）。
  • 海拔：cameraHeight 目前為相機位置的海拔，不是相機離地高度。
  • 2007 年的資料：計畫 329 有少量照片日期為 2007 年，早於計畫開始時間（2015-09），可能是相機時鐘錯誤，但因落在合理年份內未被標記，使用時請留意。
  • 照片存取：filePublic 皆為 false，照片網址可能無法直接瀏覽。
